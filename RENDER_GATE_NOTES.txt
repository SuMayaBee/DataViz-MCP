RENDER GATE + GRACEFUL FAILURE — parked feature (NOT committed, NOT applied)
================================================================================
Status : DROPPED from the working tree on 2026-07-08. This file is git-excluded
         via .git/info/exclude, so it stays local for reference and is never
         pushed. The show.html UI polish (pill shrink + animated "Refining…"
         bar-chart/shimmer) was KEPT — this note is only about the render gate.

--------------------------------------------------------------------------------
WHAT IT DID
--------------------------------------------------------------------------------
Before show() reported "success", it drew the snippet's /view page in a headless
browser and checked whether the chart actually rendered. If the draw failed, show()
returned the quiet "Refining…" retry payload (no URL) instead of a success — so a
broken chart never spilled its error into the iframe; the model just fixed the code
and retried.

--------------------------------------------------------------------------------
WHY IT EXISTED (the gap it filled)
--------------------------------------------------------------------------------
Validation runs the code (exec) but never DRAWS the chart. .servable() / a bare
last expression don't build the Bokeh model until a live browser session renders
them. So "render-time" errors (holoviews/bokeh building the model — e.g. a
categorical y-axis + xlim TypeError, pn.bind callbacks that only run at render,
overlays with mismatched axis types, degenerate/empty data) are INVISIBLE to
validation and only appear once the iframe loads /view.

Proven on the GDP bar-chart-race crash: it passed plain exec(), passed exec under
a fake curdoc, passed bokeh's CodeHandler — and only failed when a real browser
drew /view. The gate was the only thing that caught it.

--------------------------------------------------------------------------------
WHY IT WAS DROPPED
--------------------------------------------------------------------------------
Latency. The gate adds a headless-browser round-trip to every show():
  - without gate : ~0.1–1.3s
  - with gate (warm browser) : ~1.3–2s
  - with gate (first call of a session, cold browser) : ~7s
Render-time errors are rare for simple inline plots and only common for complex
interactive server dashboards (pn.bind, templates, streaming). Paying ~1–2s on
every call was judged not worth it for now.

--------------------------------------------------------------------------------
RECOMMENDED WAY TO RE-ADD (the "middle ground")
--------------------------------------------------------------------------------
Re-apply the patch below, then gate ONLY method="server" so simple inline plots
stay fast and only the risky dashboards pay the cost. In server.py show(), set:
      render_gate=(method == "server")
instead of the unconditional render_gate=True in the patch.
Everything else (probe_render, endpoint gate, friendly card) can stay as-is.

--------------------------------------------------------------------------------
HOW TO RESTORE
--------------------------------------------------------------------------------
From the repo root:
      git apply RENDER_GATE_NOTES.txt      # the unified diff below applies cleanly
(or copy the patch section into featureB.patch and `git apply featureB.patch`.)
The gate is opt-in: it only runs when the /api/snippet request body sets
"render_gate": true, so nothing changes until show() asks for it.

Files it touches (all small):
  server.py     (+6)  show() sets render_gate=True, wraps create_snippet in a thread
  client.py     (+18) create_snippet() forwards the render_gate flag, bumps timeout
  endpoints.py  (+44) async post + _render_gate() helper (loads /view, reads DB status)
  screenshot.py (+35) probe_render() / _BrowserManager.probe() — draw /view, no PNG
  view_page.py  (+49) friendly 🎨 error card w/ collapsed details (replaces traceback)

Verified when built: e2e caught the GDP TypeError before success; clean viz passed;
flag correctly gated it; 188 tests passed; no new lint.

+    async def probe(self, url: str, *, settle_ms: int, timeout_ms: int) -> None:
+        """Load ``url`` in a fresh context to force a real render, capturing no PNG.
+
+        Used by the render gate: loading ``/view`` makes the Panel server execute
+        and *draw* the snippet in a live Bokeh session — the only place render-time
+        errors (holoviews/bokeh building the model) actually fire — and persist the
+        resulting status to the database.
+        """
+        browser = await self._ensure_browser()
+        context = await browser.new_context()
+        try:
+            page = await context.new_page()
+            await page.goto(url, wait_until="load", timeout=timeout_ms)
+            # Wait for the session to mount something — the rendered viz OR the
+            # error card view_page returns — which means create_view (and its DB
+            # status write) has completed.
+            try:
+                await page.wait_for_selector(_CONTENT_SELECTOR, timeout=min(5000, timeout_ms))
+            except Exception:
+                logger.debug("Render gate: no content selector matched for %s.", url)
+            await page.wait_for_timeout(settle_ms)
+        finally:
+            await context.close()
