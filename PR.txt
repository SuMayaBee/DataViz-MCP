Title: Fix: Derive the Panel server port per environment so pls uses the right packages

## Description

**The problem:** every environment shared one fixed Panel server port (5077). When a `pls` from one
environment started while a server from another environment was already running on 5077, the new one
reused that existing server instead of starting its own. Snippets then ran in the wrong environment,
so a package the user installed alongside their `pls` (e.g. `snowflake`) came back as "not installed".

**How I solved it:** I gave each Python environment its own port, derived from the interpreter (base
5077), so they no longer collide, and made `pls` reuse a running server only when it belongs to the
same environment. Now snippets always run in the environment the user installed `pls` and their
packages into.

**Testing:** I manually tested by installing packages like `snowflake` and `cowsay` into a separate
environment alongside `pls`, then asked the assistant to visualize with them, and confirmed the
snippets ran and found the packages instead of reporting them as "not installed".
